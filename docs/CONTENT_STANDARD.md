# Content quality standard

## 验收目标

读者能在 30 秒内准确回答，能对关键结论给出机制和边界，能运行最小程序核对行为，能回答追问并说明如何测量。文章篇数、行数、装饰图和术语密度不是质量指标。

## 十一节契约

| 节                     | 必须回答                                     |
| ---------------------- | -------------------------------------------- |
| 30 秒面试回答          | 是什么、关键机制、一个重要限制               |
| 核心概念               | 术语区分、前提、与相邻概念的区别             |
| 原理深入               | 因果链/同步链/不变量，而非只列 API           |
| 数据结构/系统内部实现  | 状态与操作路径；标准保证与具体实现分开       |
| C++ runnable demo      | 完整程序、编译方法、预期行为、平台与省略范围 |
| 高频追问               | 至少覆盖两种机制或边界追问                   |
| 容易答错的点           | 给错误说法的修正与原因                       |
| 性能分析               | 指标、实验控制、复杂度和证据限制             |
| Quant/Low-Latency 场景 | 明确落到组件、数据流、背压或失败处理         |
| 相关专题               | 可用内部链接及前置/后续关系                  |
| 分层面试题             | 15–30 题、L1/L2/L3 各至少 5，答案与评分点    |

“高频”指知识结构与岗位职责推导出的高价值练习，不声称测得面试出现频率。

## 技术准确性

- 语言层：注明 C++ 版本，区分 UB、unspecified、implementation-defined；不从某次运行推导标准保证。
- 并发：画出访问者、所有权、发布与复用、生命周期和 happens-before；检查空/满/回绕/关闭。
- Linux：说明系统调用返回值、错误路径、非阻塞属性、fd 生命周期以及内核/平台差异。
- 容器：说明迭代器失效、异常、分配、平均与最坏复杂度；不要只报一段子操作的复杂度。
- 交易：区分 MBO/MBP、行情重建/撮合、会话/序列域、valid/invalid、快照/增量边界。规则来自具体协议，不声称所有交易所一致。

## 代码标准

示例必须独立编译，开启常用 warning 并视为错误，使用断言或明确错误退出验证行为。正确性测试不能依赖“某调度次序必定发生”。测试数据保持有界，避免 signed overflow、悬空引用及未初始化读取。

使用普通容器教学时明确生产局限。Linux demo 不伪装可在所有浏览器运行。模拟代码注明未实现功能；例如示范 Order Book 没有撮合、网络 feed 解析、sequence recovery，SPSC 没有通用 T 生命周期或 MPSC 支持。

代码段通过编译只证明语法和有限执行，不证明并发或系统正确。Sanitizer 的无报告也不是证明。性能 demo 不设置“加 padding 一定更快”之类脆弱断言。

## 性能结论标准

任何数值结论应保存硬件拓扑、系统/内核、编译器、编译参数、负载分布、线程与内存放置、预热、重复次数、测量点、原始分布和误差解释。没有实测时写明是预期机制或待验证假设。

同时考虑吞吐与 p50/p99/p99.9；不要用一个平均值代表尾延迟。不承诺普适 cache latency 表或固定加速倍数。指出 coordinated omission、排队、共享 CI 噪声、计时器与频率变化的风险，仅在与当前实验相关时展开。

## 来源与审查

论据 references 优先标准、Linux manual、交易所协议、编译器实现和原作者资料。每条有 URL 和访问日期；网页更新后复查适用版本。公司公开面经使用独立 source 对象，与技术论据分开。

发布前逐题检查答案是否能由正文与资料支撑、L3 是否实质涉及工程权衡、是否出现无证据的“某公司必考”。内容审查与渲染检查分开记录，明确是自审还是独立审查。

## 必须阻断发布的问题

错误同步关系、潜在 UB、无法运行的 runnable demo、错误复杂度、把平台实现写成标准保证、没有来源的公司真题、伪造测试/性能结果、坏内部链接、隐含丢失数据的业务处理、答案默认暴露导致自测失效。

拼写或排版也需修复，但不能用视觉精致掩盖技术问题。首期所有 5 篇都是示范基线，后续批量选题逐篇通过相同门槛。
